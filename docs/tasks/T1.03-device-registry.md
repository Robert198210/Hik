# T1.03 — DeviceRegistry and NetworkPolicy

Role: Developer (Auto Cost). Risk: Medium. Prerequisite: T1.02.

## Files
- `src/haca/devices/models.py`, `src/haca/devices/registry.py`, `src/haca/devices/network_policy.py`
- `tests/unit/test_registry.py`, `tests/security/test_network_policy.py`

## Interfaces
- `ResolvedDevice` (frozen dataclass or Pydantic):
  - `id`, `role`, `expected_model`
  - `host: IPv4Address`, `port: int`, `scheme`
  - `credential_ref`
- `NetworkPolicy(subnet: IPv4Network, simulation: bool)` with `check_host(ip: IPv4Address) -> None`.
  It raises `NetworkPolicyViolation(reason)` when:
  - the address is not in RFC1918 (explicit networks, not `ipaddress.is_private`), or
  - the address is not in `subnet`, or
  - the address is loopback (`127.0.0.0/8`) while `simulation=False`.
  
  Loopback is allowed only with `simulation=True`. Link-local, multicast, broadcast, the network
  address and IPv6 are always rejected.
- `DeviceRegistry(devices: list[ResolvedDevice], policy: NetworkPolicy)`:
  - validates every device with `policy.check_host` at construction
  - rejects duplicate `(host, port)`
  - `get(device_id) -> ResolvedDevice` (raises `UnknownDevice`)
  - `match(host: str, port: int, scheme: str) -> ResolvedDevice | None`: exact match only; host parsed
    strictly as IPv4 literal, so hostnames return `None`
  - `all() -> tuple[ResolvedDevice, ...]`
- `DeviceRegistry.from_config(app: AppConfig, devices: list[ResolvedDeviceConfig])`.

## Acceptance criteria
1. Rejected:
   - `8.8.8.8`
   - `192.168.1.10` when the subnet is `192.168.250.0/24`
   - `127.0.0.1` without simulation
   - `169.254.1.1`
   - `192.168.250.0`
   - `192.168.250.255`
2. `127.0.0.1` is accepted with `simulation=True`.
3. `match()` returns `None` for:
   - a hostname (`nvr.local`)
   - a wrong port
   - a wrong scheme
   - leading-zero IP forms (`192.168.250.0200`)
   - IPv6
4. Duplicate host:port across two device IDs raises at construction.
5. `mypy` strict passes for `haca.devices`.
