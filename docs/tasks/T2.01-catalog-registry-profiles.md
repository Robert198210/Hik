## 1. Endpoint registry — `src/haca/isapi/registry/endpoints.yaml` + `loader.py`

The loader builds `EndpointRule` objects (from T1.04) plus registry metadata:
`device_roles`, `variants`, `capability_gate`, `verification`, `source`, `notes`.
It replaces `phase1_endpoints.py`. Keep that module as a thin wrapper or delete it and update imports.

Validation (lint) on load:
- `id` is unique, and every entry has a `source`.
- `verification` takes one of `observed_live | documented | candidate_unverified`.
- `read_post: true` requires `post_root_elements`.
- No entry may match the denylist. Run `EndpointPolicy` on the rendered path.

## 2. Setting Catalog — `src/haca/catalog/settings.yaml` + `catalog/models.py` + `catalog/loader.py`

Entry model:
- `id`, `category`, `title`
- `device_roles`, `scope: device | channel | item`
- `sources`: list of
  - `{kind: isapi, endpoint_id, field}`, where `field` names a typed extractor field from T2.02
  - `{kind: manual, checklist_id}`
- `verification: candidate_unverified | observed_live`
- `orp_link: str | None`

Categories: `identity`, `time`, `network`, `security`, `streaming`, `recording`, `storage`, `analytics`,
`linkage`, `ptz`, `platform`.

Minimum entries (≈ 35), for example:
- identity: model, firmware
- time: time mode, NTP server
- network: addressing type
- security: HTTP enabled, HTTPS enabled, RTSP, SDK port
- streaming (main stream): codec, resolution, frame rate, bitrate mode, bitrate, smart codec
- recording: schedule mode, schedule coverage, pre/post record, track enable
- storage: HDD status, capacity, free space
- analytics: line engine enabled, line rules, field engine enabled, field regions, region entrance,
  detection targets
- linkage: per-event notification methods on the NVR
- ptz: park action enabled, park action type, patrols, presets
- platform: EZVIZ/Hik-Connect enabled
- input proxy: protocol, online

Manual-only entries (`kind: manual`), which ISAPI cannot inspect:
- `manual.dual_vca`: Display Info on Stream / Dual-VCA
- `manual.nvr_save_vca_data`: NVR "Save Camera VCA Data"
- `manual.nvr_local_smart_analysis`: NVR channel "Enable Local Smart Analysis"
- `manual.hdd_model_smr`: HDD model and SMR/CMR
- `manual.playback_markers`: human/vehicle markers visible in playback

## 3. Synthetic collection profiles (extend T1.06)

Under `src/haca/simulation/profiles/`, each profile is a full set of `index.yaml` + XML for every
registry endpoint applicable to the role. ADR-017 applies: synthetic values only, and `provenance.yaml`
must say `origin: synthetic`.

**Scenario `clean`** (`<device>/scenario-clean`): consistent with the seed ORP in architecture.md §6.
- NVR records 24/7 CMR.
- The camera line rule is enabled with targets human and vehicle.
- The NVR trigger for `linedetection` on channel 1 includes `center` and `record`.
- The protocol is HIKVISION, the HDD is ok, NTP is used everywhere, HTTPS is enabled, HTTP is enabled.

**Scenario `conflicts`** (`<device>/scenario-conflicts`):
- NVR channel 1 uses ONVIF.
- The NVR trigger for `linedetection` lacks `center`.
- The camera line engine is enabled but every LineItem is disabled.
- A field region is enabled with an empty detection target.
- A field region is enabled with no coordinates.
- The NVR schedule is MOTION on weekends.
- The HDD status is `error`.
- ptz01 has a manual time mode.
- An NVR proxy channel 2 points to `192.168.250.250`, a camera not in the device config.
- One proxy channel is offline.

**Scenario `unsupported`**: cam01 smart capabilities report `isSupportRegionEntrance=false`. For ptz01,
`ptz.park_action` returns 404 `RequestUrlNotFound`, and `platform.ezviz` returns `notSupport`.

XML skeletons to use (element local names; namespace `http://www.hikvision.com/ver20/XMLSchema`):
- `StreamingChannelList/StreamingChannel`:
  - `id` (101 main, 102 sub), `channelName`, `enabled`
  - `Video/videoCodecType`, `Video/videoResolutionWidth`, `Video/videoResolutionHeight`
  - `Video/videoQualityControlType` (CBR|VBR), `Video/constantBitRate`, `Video/vbrUpperCap`
  - `Video/maxFrameRate` (fps×100), `Video/GovLength`, `Video/SmartCodec/enabled`
- `Time`: `timeMode` (NTP|manual), `localTime`, `timeZone`.
- `NTPServerList/NTPServer`: `id`, `addressingFormatType`, `hostName`, `ipAddress`, `portNo`, `synchronizeInterval`.
- `NetworkInterfaceList/NetworkInterface`:
  - `id`
  - `IPAddress/ipVersion`, `IPAddress/addressingType`, `IPAddress/ipAddress`
  - `IPAddress/subnetMask`, `IPAddress/DefaultGateway/ipAddress`
- `AdminAccessProtocolList/AdminAccessProtocol`: `id`, `enabled`, `protocol` (HTTP|HTTPS|RTSP|DEV_MANAGE), `portNo`.
- `SmartCap`: `isSupportLineDetection`, `isSupportFieldDetection`, `isSupportRegionEntrance`.
- `LineDetection`:
  - `id`, `enabled`
  - `LineItemList/LineItem`: `id`, `enabled`, `sensitivityLevel`, `directionSensitivity`, `detectionTarget`
    (e.g. `human,vehicle`), `CoordinatesList/Coordinates/positionX|positionY`
- `FieldDetection`:
  - `id`, `enabled`
  - `FieldDetectionRegionList/FieldDetectionRegion`: `id`, `enabled`, `sensitivityLevel`,
    `timeThreshold`, `detectionTarget`, `RegionCoordinatesList/RegionCoordinates/positionX|positionY`
- `RegionEntrance`:
  - `id`, `enabled`
  - `RegionEntranceRegionList/RegionEntranceRegion`: `id`, `enabled`, `sensitivityLevel`,
    `detectionTarget`, `RegionCoordinatesList/RegionCoordinates/positionX|positionY`
- `EventTriggerList/EventTrigger`:
  - `id`, `eventType` (`linedetection`|`fielddetection`|`regionEntrance`|`VMD`|`diskfull`|`diskerror`)
  - `videoInputChannelID` (or `dynVideoInputChannelID`)
  - `EventTriggerNotificationList/EventTriggerNotification`: `id`, `notificationMethod`
    (`record`|`center`|`email`|`beep`|`IO`), `videoInputID`
- `TrackList/Track`:
  - `id` (101), `Channel`, `Enable`, `DefaultRecordingMode`, `PreRecordTimeSeconds`, `PostRecordTimeSeconds`
  - `TrackSchedule/ScheduleBlockList/ScheduleBlock/ScheduleAction`:
    - `id`
    - `ScheduleActionStartTime/DayOfWeek|TimeOfDay`, `ScheduleActionEndTime/DayOfWeek|TimeOfDay`
    - `Actions/Record`, `Actions/ActionRecordingMode` (CMR|MOTION|ALARM)
- `hddList/hdd`: `id`, `hddName`, `hddType`, `status`, `capacity` (MB), `freeSpace` (MB), `property`.
- `InputProxyChannelList/InputProxyChannel`:
  - `id`, `name`
  - `sourceInputPortDescriptor/proxyProtocol` (HIKVISION|ONVIF), `addressingFormatType`, `ipAddress`,
    `managePortNo`, `srcInputPort`, `userName` (value always `synthetic`), `streamType`
- `InputProxyChannelStatusList/InputProxyChannelStatus`: `id`, `sourceInputPortDescriptor/ipAddress`, `online`.
- `ParkAction`: `enabled`, `Parktime`, `Action/ActionType` (preset|patrol), `Action/ActionNum`.
- `PTZPatrolList/PTZPatrol`: `id`, `enabled`, `patrolName`.
- `PTZPresetList/PTZPreset`: `id`, `presetName`, `enabled`.
- `EZVIZ`: `enabled`.

These skeletons are candidates. They are not verified against real firmware (ADR-017).

## Acceptance criteria
1. The registry loads; all lint rules are enforced by tests, including that a deliberately denylisted
   entry fails to load.
2. The catalog loads. Every `isapi` source references an existing `endpoint_id`. Every manual source
   has a `checklist_id`.
3. Every profile has `index.yaml` covering every applicable endpoint for its role and scenario.
   `scan_fixture_secrets.py` reports zero findings.
4. `docs/isapi-endpoint-registry.md` is regenerated, and a test checks it is current.
5. Simulator integration test: `IsapiClient.read()` works for every registry endpoint in `scenario-clean`
   for all three devices.
