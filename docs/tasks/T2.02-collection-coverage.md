## Models (`collect/models.py`)
- `EndpointOutcome`, one of:
  - `COLLECTED`, `NOT_SUPPORTED`, `ENDPOINT_NOT_FOUND`, `AUTH_DENIED`, `TIMEOUT`, `CONNECTION_ERROR`
  - `PARSE_ERROR`, `BLOCKED_BY_POLICY`, `SKIPPED_CAPABILITY`, `SKIPPED_DEVICE_OFFLINE`
- `RawEvidence(device_id, endpoint_id, path, outcome, http_status, sub_status_code, sha256, body: bytes | None,
  collected_at: datetime, elapsed_ms)`.
- `DeviceCollection(device_id, role, identity: DeviceIdentity | None, evidence: dict[endpoint_id, RawEvidence],
  views: DeviceViews)`.
- `CollectionResult(run_started, run_finished, simulated: bool, devices: list[DeviceCollection])`.

## Capabilities
- `parse_smart_capabilities(doc) -> dict[str, bool]` produces keys like `smart.isSupportLineDetection`.
- A capability gate evaluates as follows:
  - flag present and `false` → `SKIPPED_CAPABILITY`, recorded with positive evidence
  - flag absent, or the capability endpoint failed → request the endpoint anyway (GET is read-only),
    because unknown is not unsupported

## Planner
- `plan(device: ResolvedDevice, registry) -> list[PlannedRequest(endpoint_id, params)]`:
  - filtered by `device_roles`; `{channel}` = 1 for ptz/camera
  - `denied` entries are never planned
  - order: `system.device_info` first, then `smart.capabilities`, then the rest in registry order

## Engine
- `CollectionEngine(registry, policy, egress, credential_store, timeouts, transport_factory)`.
  - `transport_factory(device)` returns the inner transport: the real `HTTPTransport`, or the simulator's
    `MockTransport`.
- `collect(devices) -> CollectionResult`:
  - devices are processed sequentially
  - if `device_info` fails with `DeviceConnectionError`/`DeviceTimeout`, all remaining endpoints are
    `SKIPPED_DEVICE_OFFLINE`
  - variants are tried in order only on `EndpointNotFound`, and the evidence records the path that
    finally answered
  - every exception maps to an `EndpointOutcome`; `PolicyViolation` → `BLOCKED_BY_POLICY` and is
    logged at WARNING
- Progress callback `on_progress(device_id, endpoint_id, outcome)`, used by the CLI and later the dashboard.

## Typed extractors (`extract.py`)
Tolerant parsing. A missing element gives `None` and a `missing_fields` entry. Never raise on structure.
Pydantic models (frozen):
- `StreamView`: id, codec, width, height, fps, bitrate_mode, bitrate_kbps, vbr_cap_kbps, smart_codec.
- `TimeView`: time_mode, local_time, time_zone.
- `NtpView`: servers.
- `NetworkView`: addressing_type, ip, gateway.
- `AdminAccessView`: protocols mapped to `(enabled, port)`.
- `VcaRuleView`:
  - kind `line|field|region_entrance`, engine_enabled
  - items: id, enabled, targets: `list[str]`, coordinate_count, time_threshold
- `TriggerView`: event_type, channel, methods: `set[str]`.
- `TrackView`:
  - track_id, channel, enable, default_mode, pre_s, post_s
  - schedule: list of `(start_day, start_time, end_day, end_time, mode, record)`
- `HddView`: id, status, capacity_mb, free_mb.
- `ProxyChannelView`: id, protocol, ip, port, online `bool | None` (joined from the status endpoint).
- `ParkActionView`: enabled, park_time_s, action_type, action_num.
- `PatrolView`, `PresetView`, `PlatformView` (ezviz_enabled).

`DeviceViews` aggregates these, with each field optional.

## Normalizer
- `flatten(doc: XmlDocument) -> dict[str, str]`: stable dotted paths using local names. A repeated element
  with an `id` child gets the index `[id]`; otherwise a positional `[n]`. Used for snapshot diff and
  `OBSERVED_UNCATALOGED`.

## Coverage (`catalog/coverage.py`)
- `compute_coverage(catalog, collection, orp) -> list[CoverageEntry]`, one entry per `(device, setting)`
  applicable to the role.
- `CoverageEntry(device_id, setting_id, status, reason, evidence_tier, endpoint_id)`, with statuses and
  reasons from architecture.md §7.
- Mapping from the endpoint outcome:
  - `COLLECTED` + field present → `VERIFIED_ISAPI`
  - `COLLECTED` + field missing → `INACCESSIBLE/field_absent`
  - `NOT_SUPPORTED` or `SKIPPED_CAPABILITY` → `UNSUPPORTED_BY_DEVICE`
  - `ENDPOINT_NOT_FOUND` → `INACCESSIBLE/endpoint_not_found`
  - `AUTH_DENIED` → `INACCESSIBLE/auth_denied`
  - `TIMEOUT` → `INACCESSIBLE/timeout`
  - `CONNECTION_ERROR` → `INACCESSIBLE/connection_error`
  - `PARSE_ERROR` → `INACCESSIBLE/parse_error`
  - `BLOCKED_BY_POLICY` → `INACCESSIBLE/blocked_by_policy`
  - `SKIPPED_DEVICE_OFFLINE` → `INACCESSIBLE/device_offline`
- Manual sources:
  - `NOT_IMPLEMENTED_IN_HACA` when no manual attestation file is provided
  - `VERIFIED_MANUAL` when an attestation file (`--manual PATH`, YAML `{device_id: {checklist_id: value}}`)
    has the item
- `NOT_APPLICABLE`: roles, plus ORP (e.g. PTZ entries when `ptz_mode` is irrelevant). Keep the ORP-based
  part minimal: only role-based in v1.
- The evidence tier is `simulation` when `collection.simulated`, otherwise `isapi`.
- `coverage_summary(entries)` → per device × category counts, plus totals and `catalog_version`.
- `OBSERVED_UNCATALOGED`: the count of flattened paths of collected endpoints not used by any extractor
  field (approximation: total flattened leaves minus extracted leaves).

## CLI
`haca collect [--simulate] [--scenario clean|conflicts|unsupported] [--json]` prints:
- the per-device outcome table
- the coverage summary
- `SIMULATED` banner when simulating

Persistence comes in T2.03; until then, the result is printed only.

## Acceptance criteria
1. `scenario-clean`: every isapi catalog entry for all devices is `VERIFIED_ISAPI`, except entries not
   applicable to the role. Manual entries are `NOT_IMPLEMENTED_IN_HACA`.
2. `scenario-unsupported`:
   - cam01 region-entrance entries → `UNSUPPORTED_BY_DEVICE`, and the endpoint is not requested
     (simulator `request_log`)
   - ptz01 park action → `INACCESSIBLE/endpoint_not_found` after trying the variant path; never
     `UNSUPPORTED`
   - ezviz → `UNSUPPORTED_BY_DEVICE`
3. A device with `connect_error` → all its entries `INACCESSIBLE/device_offline`. Other devices are unaffected.
4. Extractors tolerate a missing element (dedicated test with a stripped XML) and record `missing_fields`.
5. A wrong password on one device → `INACCESSIBLE/auth_denied` for its entries, with no retry storm
   (≤ 2 requests per endpoint in `request_log`).
6. The simulator `request_log` contains only GET.
