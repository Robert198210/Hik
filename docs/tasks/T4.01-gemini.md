# T4.01 — Gemini analysis (v0.2): adapter, payload, validator, usage, fallback, HTML report

Role: Developer (Auto Cost). **Risk: High → gate S3.** Prerequisite: MVP (T3.02).
References: ADR-003, ADR-011, ADR-016, [architecture.md §8–9](../architecture.md).

## Constraints
- Google Gemini via `google-genai` is the only AI provider. No other AI SDK.
- Tests never call the network. Use a fake client implementing the same small interface.
- No API key is ever written to config, logs, reports, DB, or exceptions.

## Adapter (`client.py`)
- `AiClient` Protocol:
  - `generate(prompt: str, payload_json: str) -> AiCallResult(parsed: AiAnalysis | None, raw_text, input_tokens, output_tokens, total_tokens, model, latency_ms)`
  - `count_tokens(text) -> int`
  - `list_models() -> list[str]`
- `GeminiClient(api_key: SecretStr, model: str, temperature=0.2, max_output_tokens=4096)`:
  - `google.genai.Client(api_key=...)`
  - `client.models.generate_content(model=..., contents=[prompt, payload_json],
    config=types.GenerateContentConfig(response_mime_type="application/json", response_schema=AiAnalysis,
    temperature=..., max_output_tokens=...))`
  - uses `response.parsed`; on parse failure, one retry with a repair instruction, then gives up
  - token counts from `response.usage_metadata` (`prompt_token_count`, `candidates_token_count`,
    `total_token_count`)
- Egress:
  - If the installed SDK supports injecting httpx client args (`types.HttpOptions(client_args=...)`
    or similar), inject a transport that applies `EgressPolicy(allow_gemini=True)`.
  - Otherwise, assert at construction that the base URL host is `generativelanguage.googleapis.com`.
  - Document which path was used in the module docstring.
- The key comes from `CredentialStore`-like lookup: keyring `haca` / `gemini_api_key`, else env
  `GEMINI_API_KEY`. The key is registered with `register_secret`.
- Model ID comes from config `ai.model` (no hard-coded default name). `haca ai models` lists available
  models when a key is set.

## Payload (`payload.py`)
- `build_payload(report: AuditReport, views, orp, catalog, budget_chars) -> AiPayload`:
  - included:
    - ORP
    - coverage summary
    - deterministic findings (id, rule, classification, severity, current/recommended)
    - per device: role, model, firmware, and the extracted views as `setting_id → value` for
      `VERIFIED_ISAPI` entries only
  - removed:
    - serials, MACs, deviceID, usernames
    - free-text names (`channelName`, rule names, `patrolName`, `presetName` → `item-<id>`)
    - IPs → `<subnet>.<last-octet>`
    - raw XML
  - trimming order when over budget: drop INFO findings, then streaming sub-streams, then presets
- `haca ai preview [--simulate --scenario X]` prints the exact payload JSON and the estimated token count
  without sending anything.

## Schema (`schema.py`)
- `AiAnalysis(summary: str, suggestions: list[AiSuggestion], cross_device_notes: list[str])`
- `AiSuggestion`:
  - `device_id`, `setting_id`, `current_value: str | None`, `recommended_value: str | None`
  - `classification: Literal["POTENTIAL_CONFLICT", "OPTIMIZATION", "INFO"]`
  - `severity: Literal["high", "medium", "low", "info"]`
  - `rationale`, `depends_on: list[str]`
- AI can never emit `CONFIRMED_CONFLICT` or `critical`; the schema disallows them.

## Prompt (`prompts.py`)
- Versioned `PROMPT_VERSION`.
- The prompt instructs the model to:
  - use only settings present in the payload, and never invent settings or values
  - respect ORP explicit values and treat undecided as a question
  - cite `setting_id`s
  - keep the output JSON-only
- The knowledge file (`hikvision-acusense.md`) is appended. It is curated generic domain knowledge,
  each point with a public-source note:
  - camera-side analytics + NVR by-camera mode
  - Hikvision protocol vs ONVIF for smart metadata
  - Dual-VCA / Save VCA data for timeline markers
  - continuous recording vs event recording
  - SMR disks and intelligent search
  - VCA rules and PTZ movement

## Validator (`validator.py`)
For every suggestion:
1. `device_id` exists in the report.
2. `setting_id` exists in the catalog and is applicable to the device role.
3. `current_value` equals the observed value: normalized string compare, case-insensitive, trimmed.
   If the setting is not `VERIFIED_ISAPI`/`VERIFIED_MANUAL` → reject (`unobserved_setting`).
4. `recommended_value` must be in the catalog entry's `known_values` when present. Otherwise accept,
   with `capability_verified=false`.
5. Reject if it contradicts an explicit ORP value linked via `orp_link`.
6. If it duplicates a deterministic finding (same device + setting), attach it as `ai_corroboration`
   to that finding instead of adding a new one.

Accepted suggestions become `Finding(source="ai_validated", basis="technical", evidence=[EvidenceRef from
the observed value])`. Classification never exceeds `POTENTIAL_CONFLICT`. Rejected suggestions go to
`report.ai.rejected` with a reason.

## Usage, budget, cache (`usage.py`, store schema v2)
- Store migration `user_version` 1 → 2 (forward-only function plus test) adds:
  - `ai_calls`: run_id, model, prompt_version, input_tokens, output_tokens, total_tokens,
    est_cost (nullable), latency_ms, payload_sha256, status
  - `ai_cache`: key, response_json, created_at
- Cost = tokens × `ai.pricing[model]` from config (`input_per_mtok`, `output_per_mtok`). Missing pricing
  → cost `null` ("unknown").
- Budget:
  - `ai.max_input_tokens`: `count_tokens` before the call; over budget → trim; still over → skip AI with
    reason `budget_exceeded`
  - `ai.max_calls_per_audit = 1` (plus one repair retry)
- Cache key = sha256(model + PROMPT_VERSION + payload_json). A cache hit → no call, `cached=true`.

## Fallback
- `haca audit --ai`:
  - no key, SDK not installed, network error, invalid response, or budget exceeded → deterministic report
    with `report.ai.status` and reason
  - exit code unaffected by AI
- Without `--ai`, nothing AI-related runs or imports. `google.genai` is imported lazily inside
  `GeminiClient`.

## HTML report
Jinja2 template rendering the same sections as Markdown, plus AI section (accepted, corroborations,
rejected). Self-contained HTML, inline CSS, no external assets. Autoescape on.

## Acceptance criteria
1. Fake client returning valid suggestions → accepted findings with `source=ai_validated`, never CONFIRMED.
2. Fake client returning hallucinations → each lands in `ai.rejected` with the expected reason:
   - unknown setting
   - wrong `current_value`
   - unknown device
   - an ORP-contradicting recommendation
3. Payload security test: for the `conflicts` scenario, the payload contains no serial, MAC, deviceID,
   `userName`, rule/channel names, raw XML, or registered secrets. IPs appear only in `<subnet>.N` form.
4. A missing key, a missing SDK (simulate `ImportError`) or an exception → report generated, `ai.status`
   set, exit code identical to the non-AI run.
5. Cache: second identical run → no client call. Usage rows record tokens. Missing pricing → `null` cost.
6. Migration 1 → 2 is tested on a v1 database file.
7. `test_dependencies.py` still passes: `google-genai` is allowed; no other AI SDK.
8. The HTML report is produced by `--format html` and passes the masking scanner.
