# T1.08 — Device identification service and `haca identify`

Role: Developer (Auto Cost). Risk: Low. Prerequisite: T1.07.

## Files
- `src/haca/collect/identify.py`, `src/haca/cli.py` (extend)
- `src/haca/simulation/defaults.py`: built-in simulated config:
  - subnet `127.0.0.0/8` is **not** used
  - the simulated network is keyed on `192.168.250.200/201/202:80` while `simulation=True`
  - the guard still validates hosts against the registry
- `tests/unit/test_identify.py`, `tests/integration/test_cli_identify.py`

## Models
- `DeviceIdentity`:
  - `device_id`, `model`, `device_type`
  - `firmware_version: str`, `firmware_major/minor/patch: int | None`, `firmware_build: str | None`
  - `serial_masked`: last 4 characters only, e.g. `****0001`
  - `mac_masked`: `**:**:**:**:53:01` style
- `IdentificationStatus`:
  - `IDENTIFIED`, `MODEL_MISMATCH`, `AUTH_FAILED`, `UNREACHABLE`, `NOT_SUPPORTED`, `ENDPOINT_NOT_FOUND`
  - `POLICY_BLOCKED`, `ERROR`
- `IdentificationResult(device_id, status, identity: DeviceIdentity | None, message: str, simulated: bool)`.

## Logic
- `identify(client, device) -> IdentificationResult`: `read("system.device_info")`, then map:
  - `model` compared with `expected_model` by exact string equality after `strip()`. `DS-7616NXI-K2`
    is **not** equal to `DS-7616NXI-K2(D)`.
  - firmware parsed with `^V(\d+)\.(\d+)\.(\d+)`. A missing or odd format keeps the raw string and sets
    the parts to `None`.
  - exceptions map to statuses. `PolicyViolation` → `POLICY_BLOCKED` (logged, never swallowed silently).
- Devices are processed sequentially. One failing device never aborts the others.

## CLI
- `haca identify [--config PATH] [--devices PATH] [--simulate] [--json]`.
  - `--simulate` ignores real config, uses `simulation/defaults.py` and the synthetic profiles, and
    prints the banner `SIMULATED — synthetic fixtures, no real device contacted`.
  - Table output: id, status, model, firmware, serial (masked).
  - `--json` returns a list of `IdentificationResult` dumps including `"simulated": true/false`.
  - Exit codes: 0 when all are `IDENTIFIED`, 2 when any other status, 1 on config error.
- `haca requirements validate --file PATH [--devices PATH]` prints the ORP hash and the list of
  `undecided`/`unspecified` fields (`needs_decision`).

## Acceptance criteria
1. `uv run haca identify --simulate` lists nvr01, ptz01, cam01 as `IDENTIFIED`, shows the SIMULATED banner,
   and exits 0.
2. A simulation variant with ptz01 `model` changed to `DS-2DE4425IW-DE` (test-only profile) → `MODEL_MISMATCH`,
   exit 2.
3. ptz01 with `connect_error` → `UNREACHABLE`. The other two are still identified.
4. `--json` output validates against `IdentificationResult` and contains no unmasked serial or MAC.
5. `haca requirements validate --file config/requirements.example.yaml` exits 0 and lists `hik_connect`
   and `ptz01.ptz_mode` as needing a decision.
