# T7.01 — Windows install scripts, live-validation prep (P3L), packaging, E2E (v1.0)

Role: Developer (Auto Cost). Risk: Medium. Prerequisites: T3.02 for the P3L part, T6.01 for packaging.
Covers plan items T3L.01–T3L.02 and T7.01–T7.06. The live run itself (T3L.03–T3L.04) happens on the
private Windows 10 PC (B3) and is outside this task.

## Files
- `scripts/windows/install.ps1`, `start.ps1`, `diagnose.ps1`, `uninstall.ps1`

## PowerShell scripts (Windows 10 x64, PowerShell 5.1 compatible)
- `install.ps1`:
  1. check `py -3.12` exists, else print the python.org instructions and exit 1
  2. create `.venv`
  3. `pip install --require-hashes -r requirements.lock`, then `pip install --no-deps <wheel>`
  4. optional `-WithBrowser` switch: `pip install playwright` + `playwright install chromium`
  5. copy `config\*.example.yaml` to the real names if absent
  6. print the next steps (set credentials, edit subnet)
  
  Uses `Set-StrictMode -Version Latest` and `$ErrorActionPreference='Stop'`. No admin rights required.
- Credentials: `install.ps1 -SetCredential <ref>` prompts with `Read-Host -AsSecureString` and stores
  via `python -m haca credentials set <ref>`. Add this CLI subcommand: it reads from stdin without echo
  (`getpass`) and writes to keyring. This is the only credential write HACA has; it is local and never
  touches devices. The ADR-004 store is extended with `set` for this command only.
- `start.ps1`: activates the venv, runs `python -m haca serve`, opens `http://127.0.0.1:8765`.
- `diagnose.ps1`: prints Python version, venv, package version, keyring backend, config validation
  (`haca config check`), and TCP reachability of device ports (`Test-NetConnection`, no HTTP).
  No secrets in the output.
- `uninstall.ps1`: removes `.venv`. Asks before removing `data\` and `reports\`.

## CLI additions
- `haca config check`: validates all config files plus ORP and prints a summary.
- `haca credentials set|status <ref>`: status shows only present / absent.

## Live-validation runbook (`docs/live-validation-runbook.md`)
Step-by-step for the private PC, following the Gate L checklist in `docs/security-review.md`:
1. account preparation by the user
2. config
3. `haca identify` only
4. inspect the request log
5. `haca collect`
6. `haca audit`
7. record the results in `docs/test-results.md`
8. update registry `verification` (procedure: `tools/registry_mark_live.py --run <run_id>` sets
   `observed_live` for endpoints `COLLECTED` in a live run, recording firmware and date)

Also add `tools/registry_mark_live.py` with tests on a simulated DB, where it must refuse simulated runs.
Live outputs stay on the private PC.

## Packaging
- The wheel contains only `haca/**`, including profiles, templates, static files, catalog and registry YAML.
- The sdist excludes `.cursor/`, `AGENTS.md`, `docs/tasks/`, `tests/`, and `.cursorignore`.
- `tools/make_release.py` builds `dist/haca-<version>-win.zip` with:
  - the wheel, `requirements.lock`, `scripts/windows/`
  - `config/*.example.yaml`
  - `README.md`, `docs/user-guide.md`, `docs/troubleshooting.md`, `docs/live-validation-runbook.md`
  - `LICENSE` if present
- `test_packaging.py` builds the wheel and sdist (`uv build`) and the zip, then asserts:
  - no `.cursor`, `AGENTS.md`, `docs/tasks`, `tests/`, or `.har` anywhere
  - no `anthropic`/`openai`/`claude`/`cursor` strings in `requirements.lock`

## E2E (simulation)
`tests/e2e/test_e2e_simulation.py` runs the CLI as subprocesses:
1. `config check` (example configs pointed at a temp dir)
2. `identify --simulate`
3. `collect --simulate`
4. `audit --simulate --scenario conflicts --format json,md,html`
5. `runs list`
6. `diff`

It asserts exit codes, files, banners, and masking.

## Acceptance criteria
1. All E2E and packaging tests are green.
2. PowerShell scripts parse:
   - if `pwsh` is available, a test runs `pwsh -NoProfile -Command "[System.Management.Automation.Language.Parser]::ParseFile(...)"`
     on each script with zero errors
   - otherwise the test is skipped and the Windows validation item in `docs/test-results.md` is marked
     "pending — private Windows 10 PC"
3. `registry_mark_live.py` refuses simulated runs and updates only `COLLECTED` endpoints of live runs.
4. `requirements.lock` has hashes and installs nothing AI-related besides `google-genai` and its
   dependencies.
5. The runbook and troubleshooting docs exist and reference the real CLI commands. Commands are
   verified by `--help` tests.
