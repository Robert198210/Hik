## Orchestrator
`run_audit(app_config, devices, orp, catalog, registry, *, simulate, scenario, manual_attestations=None,
db_path=None, ai=None) -> AuditReport`. Steps:
1. identify
2. collect
3. coverage
4. persist the collect run
5. correlate
6. rules
7. persist findings (`kind=audit`)
8. build the report

The `ai` parameter is reserved for v0.2 and defaults to `None`.

## Report model (`AuditReport`, canonical JSON)
- `meta`:
  - `haca_version`, `run_id`, `started_at`, `finished_at`
  - `simulated`, `scenario`
  - `orp_hash`, `catalog_version`, `registry_verification_counts`
- `devices`: id, role, expected_model, identity (masked), identification status
- `coverage`:
  - summary matrix: device × category × status counts
  - full entries
  - `observed_uncataloged` count
  - the fixed sentence: "Verified X of N settings in HACA catalog vY. The catalog does not cover every
    Hikvision setting."
- `findings`, sorted
- `needs_decision`: the list of ORP fields with the findings that raised them
- `manual_checks`: manual catalog items not yet attested
- `ai`: `null` in MVP

## Masking (`masking.py`)
Applied to every report output:
- serials: last 4 characters
- MAC addresses: last 2 octets
- `userName` values → `***`

IPs stay visible: they are local and configured by the user. Masking applies to findings `current_value`
too when the setting is an identifier.

## Markdown report
Sections, in order:
1. Banner: `SIMULATED` when simulated.
2. Summary: counts by classification and severity.
3. Needs decision.
4. Findings: grouped by severity. Each finding shows the table `Current → Recommended`, rationale,
   evidence (`endpoint_id` + xpath + observed value), basis, ORP refs.
5. Coverage matrix: device × category.
6. Not inspectable via ISAPI (manual checks).
7. Unsupported / inaccessible list with reasons.
8. Method and limitations: candidate endpoints, synthetic data note when simulated.

Rendered with plain Python string building; no Jinja2 in MVP.

## CLI
`haca audit [--simulate] [--scenario clean|conflicts|unsupported] [--requirements PATH] [--manual PATH]
[--out DIR] [--format json,md] [--db PATH]`:
- writes `<out>/haca-audit-<run_id>.json` and `.md`; `out` defaults to `reports/`
- prints the summary and the file paths
- exit codes:
  - 0: no CONFIRMED (and no `simulated_confirmed`)
  - 3: findings ≥ high
  - 1: error

## Acceptance criteria
1. `uv run haca audit --simulate --scenario conflicts --out <tmp>` writes JSON and MD. The JSON validates
   against `AuditReport`. The MD contains the SIMULATED banner and a coverage matrix.
2. No unmasked serial, MAC or `userName` value appears in JSON or MD (scanner test).
3. `scenario-clean` exits 0. `scenario-conflicts` exits 3.
4. Report JSON is deterministic except timestamps and `run_id`. Compare two runs after removing those keys.
5. A manual attestation file turns `manual.dual_vca` into `VERIFIED_MANUAL` in coverage.
