# ISAPI Endpoint Registry

The machine-readable source of truth is `src/haca/isapi/registry/endpoints.yaml` (created in T2.02).
This document describes the schema and policy. From T2.02 on, the endpoint table below is generated by
`tools/registry_report.py`. Do not edit the table by hand.

## Entry schema

```yaml
- id: system.device_info                 # stable, dotted
  path: /ISAPI/System/deviceInfo         # path template; {channel} etc. allowed
  method: GET                            # GET, or POST only with read_post: true
  read_post: false
  body_template: null                    # required when read_post: true
  device_roles: [nvr, ptz, camera]
  variants: []                           # alternative paths for other firmware, tried in order
  capability_gate: null                  # capability path that must be true, or null
  sensitivity: normal                    # normal | sensitive | denied
  redaction_profile: identity            # applied before storage/report/AI
  verification: candidate_unverified     # observed_live | documented | candidate_unverified
  source: "<where this entry comes from>"
  notes: ""
```

## Policy

- No entry without `source`. Unknown provenance means `candidate_unverified`.
- `verification: observed_live` is set only from live validation on the private Windows 10 PC (P3L),
  with firmware version and date recorded in `docs/test-results.md`.
- Per ADR-017, private captures are not used. Until P3L, every entry is `documented` (public Hikvision
  documentation reference given in `source`) or `candidate_unverified`.
- `sensitivity: denied` entries are never requested. They are listed so the policy can refuse them explicitly:
  - full configuration export: `/ISAPI/System/configurationData`
  - snapshot images: `/ISAPI/Streaming/channels/{id}/picture` (denied by default; privacy)
- The only POST permitted is a log/content search with a fixed body template (`read_post: true`), and
  it is disabled by default.

## Denylist (path patterns, method-independent)

Denylist matches override the allowlist. The final list is defined in T1.04. Minimum patterns:

- `reboot`, `factoryReset`, `factoryDefault`
- `upgrade`, `updateFirmware`, `firmware`
- `configurationData`
- `PTZCtrl/.*/(continuous|momentary|absolute|relative|presets/.+/goto|homeposition|patrols/.+/start|auxcontrols)`
- `Storage/hdd/.*/format`, `format`
- `Security/users`
- `activate`, `password`
- `/SDK/`, `/PSIA/`, `/cgi-bin/`

## Coverage linkage

Each Setting Catalog entry (`src/haca/catalog/settings.yaml`) references the `endpoint_id` and XPath
it is read from. Coverage statuses: see [architecture.md §7](architecture.md).
